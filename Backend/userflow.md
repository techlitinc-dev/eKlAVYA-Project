# Mentor AI — User Flows

This document describes the end-to-end user journeys of the Mentor AI platform: a parent-guided exam prep system for JEE Main, JEE Advanced, NEET, and MHT CET. It is grounded in the actual routers and endpoints in `main.py`, `routers/`, and `middleware/`.

## Actors

- **Parent** — registers the account, manages the child profile, selects the exam, reviews progress, and pays for subscriptions. Authenticates via `/login/email` (JWT).
- **Student (Child)** — the exam candidate. Gets a username/password generated by the parent and authenticates via `/login/child`. Studies, takes tests, and interacts with AI features.
- **Backend roles** — Firebase Auth (identity), Firestore (data), Gemini API (AI planning/analytics/question generation), FAISS vector search (syllabus RAG), Razorpay (payments).

## High-Level Journey

```
Parent                                Student
  │                                     │
  ├─ 1. Register (email/phone/Google)   │
  ├─ 2. Verify email                    │
  ├─ 3. Create child profile ──────────►│ (receives username/password)
  ├─ 4. Set preferences                 │
  ├─ 5. Select exam + date ────────────►│
  │                                     ├─ 6. Login
  │                                     ├─ 7. Take diagnostic test (200 Qs)
  │        ◄── Gemini analytics ────────┤
  ├─ 8. View analytics ────────────────►│
  │        ─── AI study schedule ──────►│
  │                                     ├─ 9. Daily study loop (Study Center, practice, doubts)
  │                                     ├─ 10. Practice tests / quick practice
  ├─ 11. Monitor dashboards/goals ◄─────┤
  ├─ 12. Subscribe (Razorpay) ─────────►│ (unlocks premium features)
```

Onboarding status is tracked centrally and queryable at any point: `GET /api/onboarding/status?parent_id=...`.

## Flow 1: Parent Registration & Verification

Goal: a verified parent account exists in Firebase Auth + Firestore.

1. **Register** — one of:
   - `POST /register/parent/email` — `{name, email, password, mobile}`
   - `POST /register/parent/phone` — `{name, mobile, password, email}`
   - `POST /register/parent/google` — Google OAuth (mock supported in testing)
2. **Verify email** — `POST /verify/email/send`, then `POST /verify/email/confirm` with the 6-digit code. Phone verification has a parallel path (`/verify/phone/...`).
3. **Login** — `POST /login/email` → JWT access token. Profile via `GET /me`.
4. **Session management** — token refresh/refresh-token endpoints in `login_router.py`.

New accounts start on the `free` plan (`subscription_status: FREE` in the parents doc).

## Flow 2: Child Onboarding

Goal: the parent's account has a child profile, and the student can log in independently.

1. **Create child** — `POST /api/onboarding/child` (parent token) with `{parent_id, name, age, grade, current_level}` → `child_id`.
2. **Student credentials** — generated as part of onboarding; the student logs in with username/password at `POST /login/child` (see `routers/login_router.py`, `middleware/testing_auth.py`).
3. **Child profile access** — `GET /api/onboarding/child?parent_id=...` (parent), `GET /me/child` (student token).
4. **Multiple children** — `child_router.py` supports profile management and deletion.

## Flow 3: Preferences & Exam Selection

Goal: onboarding is complete — exam, date, and subject weightings are known.

1. **Preferences** — `POST /api/onboarding/preferences`: language, notification settings (email/SMS/push), teaching involvement.
2. **Pick exam** — `GET /api/onboarding/exams/available` lists supported exams with dates (`data/exam_dates.json`); `POST /api/onboarding/exam/select` with `{parent_id, exam_type, exam_date, subject_preferences}` e.g. Physics 40 / Chemistry 35 / Math 25.
3. **Check status** — `GET /api/onboarding/status` returns which onboarding phases are done (registration → preferences → exam → diagnostic scheduled).
4. Exam metadata lives in `data/exam_patterns/` (10-year pattern analysis drives diagnostic question distribution).

## Flow 4: Diagnostic Test (the calibration event)

Goal: baseline measurement of the student's level, feeding everything downstream.

1. **Generate/list** — diagnostic tests are listed via `GET /api/testing/diagnostic/list`; generation uses the exam pattern (200 questions, topic weightage, negative marking per exam type).
2. **Start** — `POST /api/testing/diagnostic/start` (student token) `{child_id, diagnostic_test_id}`.
3. **Answer/submit** — answers submitted via `POST /api/testing/diagnostic/submit`; the test is scored (overall + per-topic).
4. **Results** — `GET /api/testing/diagnostic/results/{test_id}`.

## Flow 5: Analytics → Adaptive Study Schedule

Goal: turn diagnostic results into a day-by-day plan.

1. **Analytics** — Gemini Flash analyzes results (`services/analytics_service.py`, `utils/analytics_prompt_templates.py`): weak subjects (<60%), weak topics with accuracy %, improvement strategies, and parent guidance.
2. **Schedule generation** — `POST /api/schedule/...` via the adaptive scheduler considers exam date, days remaining, topic weightage, and preferred study times; outputs daily tasks (4–6 hrs/day), weekly milestones, monthly goals.
3. **Rescheduling** — missed sessions or practice-test performance trigger adaptive reschedule (`POST /api/schedule/reschedule` with reason `MISSED_SESSION` | `PRACTICE_TEST`).

## Flow 6: Daily Student Learning Loop

Goal: the student's everyday study experience.

1. **Today's plan** — `GET /api/student/today/{child_id}` (student dashboard) shows scheduled tasks.
2. **Study Center** (`study_center_router.py`):
   - Select a syllabus topic → system checks the **material cache** first (500 ms target for cache hits, 30-day reuse window, 10 generations/hour/student rate limit).
   - Miss → Gemini generates notes → cached for all students.
   - **Mind maps** — Gemini-generated JSON, ≥3 hierarchy levels, cached in both JSON and text form.
   - **Teaching content** — structured intro/key concepts/≥2 worked examples/summary, difficulty adapted to exam type.
   - **Progress tracking** — session start/stop, completion %, time per topic; drives learning-journey sequencing (prerequisites, next recommended topic).
3. **Quick practice** — `POST /api/student/practice/quick` for a 15-minute burst.
4. **Doubts** — `POST /api/student/doubts` → AI explanation at `GET /api/student/doubts/{doubt_id}/explanation`.
5. **Gamification** (`gamification_router.py`) — badges, achievements, streaks, and motivational feedback along the way.

## Flow 7: Practice Testing & Question Generation (RAG)

Goal: continuous targeted practice.

1. **Generate questions** — `POST /api/rag/generate-questions` (single topic) or `/api/rag/generate-batch` (multiple topics): `{topic(s), exam_type, difficulty, num_questions, question_type}`.
2. **Pipeline** — syllabus embeddings (`data/embeddings/` + FAISS via `embedding_router` / `vector_search_router`) retrieve context; Gemini generates pattern-matched questions with explanations. Cache-first via `use_cache`.
3. **Test lifecycle** — `POST /api/testing/test/generate|start|submit`; results and per-topic accuracy flow back into analytics.
4. **Syllabus coverage** — `syllabus_coverage_router.py` tracks coverage vs. the official syllabus.

## Flow 8: AI Features

- **AI Tutor** — `POST /api/ai/tutor/ask` (contextual Q&A with chat history at `GET /api/ai/tutor/history/{student_id}`).
- **Exam readiness** — `GET /api/ai/readiness/{child_id}`.
- **Mistake analysis** — `GET /api/ai/analysis/mistakes/{child_id}`.
- **Recommendations** — topics (`/api/ai/recommend/topics/{child_id}`) and resources (`/api/ai/recommend/resources/{topic_id}`).

## Flow 9: Parent Monitoring Loop

Goal: the parent supervises without teaching.

1. **Dashboard** — `GET /api/parent/dashboard/{child_id}`: progress, schedule adherence, analytics summary.
2. **Reports** — weekly reports (`GET /api/parent/reports/weekly/{child_id}`), email report scheduling (`POST /api/parent/reports/email-schedule`).
3. **Notifications** — settings at `GET/PUT /api/parent/notifications/settings`.
4. **Goals** — `POST /api/parent/goals/{child_id}` (e.g., "Complete Physics syllabus by Apr 30"), tracked alongside the schedule.

## Flow 10: Subscription & Payments

Goal: convert free users to premium (parent-initiated, Razorpay-backed).

Plans (`data/subscription_plans.json`): `free`, `premium_monthly`, `premium_yearly`.

1. **Browse plans** — `GET /api/payment/plans`.
2. **Create order** — `POST /api/payment/create-order` `{parent_id, plan_id}`.
3. **Verify payment** — `POST /api/payment/verify` (Razorpay signature check; test mode supported).
4. **Manage** — subscription status `GET /api/payment/subscription/{parent_id}`, transaction history, cancellation.
5. **Gating** — `middleware/subscription_middleware.py` provides `require_premium_subscription` / `check_feature_access` dependencies; premium-only endpoints return 403 for free users, while some endpoints degrade gracefully (`get_subscription_or_free`).

## Data Dependencies Between Flows

| Flow | Produces | Consumed by |
|---|---|---|
| Registration + child onboarding | `parent_id`, `child_id`, student credentials | Everything |
| Preferences + exam selection | exam type/date, subject weightings | Diagnostic generation, scheduling, RAG question gen |
| Diagnostic test | scores per subject/topic | Analytics, schedule generation, readiness |
| Analytics | weak topics, strategies | Schedule, recommendations, parent dashboard |
| Schedule | daily tasks, milestones | Today's plan, rescheduling |
| Study Center + tests | progress, accuracy, coverage | Analytics refresh, gamification, parent reports |
| Payments | plan entitlement | Feature gating across AI/learning features |

## Failure & Edge Cases

- **Unverified email** — verification endpoints enforce confirmation before full access.
- **Auth failures** — 401 with `Bearer <JWT>` required; parent vs. child tokens hit different `/me` endpoints; child/parent ownership is checked (403 on mismatch).
- **Rate limiting** — `RateLimitMiddleware` globally; per-student caps on AI generation (10/hour).
- **AI degradation** — `mock_gemini_client.py` supports testing without live Gemini; cached materials serve repeated requests.
- **Expired subscription** — gated endpoints 403; status readable via `get_subscription_or_free`.
